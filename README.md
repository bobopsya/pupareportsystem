# ZhukoNet — портал сотрудников

Внутренний веб-портал кибербез-компании ZhukoNet: сотрудники, клиенты, общий менеджер паролей, реестр сетей ZeroTier, учёт и USB-консоль для ESP32 / Arduino Uno. Тёмная монохромная тема, интерфейс на русском, работает на ПК и телефоне.

## Возможности

| Раздел | Что умеет |
|---|---|
| **Вход** | Логин + пароль (argon2id). Временный пароль при создании, обязательная смена при первом входе. Автовыход через 30 мин бездействия. Блокировка IP на 15 мин после 5 неудачных попыток. |
| **Дашборд** | Счётчики, онлайн-статусы узлов ZeroTier, задачи команды, последние действия. |
| **Задачи** | Общий список: исполнитель, срок, клиент, отметка «готово». |
| **Отметки** | Каждый сотрудник раз в день отмечается «на связи» до 00:00 МСК (включая выходные) — кнопкой на дашборде или в Telegram-боте. Таблица отметок за 14 дней. Кто не отметился — после полуночи бот публикует в канал общий текст, который сотрудники редактируют на сайте (подстановки `{имя}`, `{логин}`, `{должность}`, `{дата}`). Сотрудники в отпуске не учитываются. |
| **Telegram-бот** | Отметка, напоминания в 20:00 и 23:00 МСК, поиск клиента по имени/телефону/email, просмотр карточки, правка полей (контакты, адрес, геопозиция, статус, теги, заметки), новый клиент, история (добавить, изменить, удалить), фото к клиенту, мои задачи (отметить выполненной), мои выезды на сегодня. Работает только для привязанных сотрудников; все действия пишутся в журнал. |
| **Сотрудники** | Карточки или таблица, поиск и фильтры. Должность, отдел, контакты, навыки и сертификаты, статус, дата найма. «Уволен» блокирует вход. Любой сотрудник может добавить нового. |
| **Клиенты** | Частные лица. Контакты, мессенджеры, адрес объекта, документы, тариф, ответственный, теги, свои поля. Вкладки: инфраструктура (устройства, IP, MAC), фото (галерея), файлы, история (звонки, выезды), пароли клиента. Экспорт всех данных в ZIP и удаление навсегда по GDPR/DSGVO. |
| **Пароли** | Общее хранилище со сквозным шифрованием (AES-256-GCM в браузере). Мастер-ключ компании и код восстановления. Умный импорт любого JSON (вложенные структуры, Bitwarden и др.) с предпросмотром и поиском дублей. Генератор, проверка стойкости, подсветка повторов. Буфер обмена очищается через 30 с. Экспорт в JSON/CSV. |
| **ZeroTier** | Реестр сетей: Network ID, клиент, подсети, маршруты, узлы и их владельцы. Синхронизация с my.zerotier.com подтягивает узлы и их онлайн-статус. Инструкции по подключению для Windows, Linux и macOS. |
| **Устройства** | Реестр ESP32 / Uno: чип, MAC, USB VID/PID, flash, прошивка и версия, у кого сейчас, история передач. |
| **USB-консоль** | Web Serial в Chrome/Edge: выбор скорости, лог с временем, сохранение лога, шаблоны команд, автоопределение платы, плоттер, чтение чипа и MAC у ESP32, «Добавить в реестр» в один клик. |
| **Журнал** | Входы, изменения и просмотры паролей с фильтрами. |
| **Корзина** | Удалённое хранится 30 дней, потом стирается автоматически. |
| **Настройки** | Смена пароля, API-токен ZeroTier, Telegram-бот (токен и канал), смена мастер-ключа, скачивание бэкапа. |

## Как устроено

```
Браузер ──HTTPS──► Caddy / nginx ──► app (Node.js 22, Fastify) ──► /data
                                                                   ├─ portal.db  (SQLite, зашифрована DB_KEY)
                                                                   └─ files/*.bin (AES-256-GCM, FILES_KEY)
```

- `server/`: API на Fastify. SQLite с шифрованием (better-sqlite3-multiple-ciphers), проверка данных через zod, sharp для фото (сжатие, удаление EXIF/GPS, миниатюры).
- `web/`: React + TypeScript + Tailwind (Vite). Шрифты и иконки встроены, внешних запросов нет (строгий CSP).
- `deploy/`: скрипты установки и обновления, конфиги Caddy и nginx.
- Всё работает на одном VPS. GitHub Pages не используется: ему нужен бэкенд, а Web Serial и Web Crypto требуют HTTPS.

**Безопасность.** Пароли хранилища шифруются в браузере, сервер видит только шифротекст. Ключ данных обёрнут ключом из мастер-пароля (PBKDF2-SHA256, 600 000 итераций) и отдельно ключом из кода восстановления. Смена мастер-ключа только переобёртывает ключ. База и файлы на диске зашифрованы ключами сервера. Cookie сессии `HttpOnly; Secure; SameSite=Strict`, на запись нужен CSRF-заголовок. Заголовки: CSP, HSTS, `X-Frame-Options: DENY`.

## Установка на VPS

Нужен Ubuntu/Debian-сервер с публичным IP.

```bash
sudo git clone https://github.com/bobopsya/pupareportsystem.git /opt/zhukonet
cd /opt/zhukonet
sudo ./deploy/install.sh
```

Скрипт по шагам:
1. ставит Docker, если его нет (спросит разрешения);
2. определяет IP и адрес вида `https://1-2-3-4.sslip.io` (свой домен: `sudo DOMAIN=portal.example.com ./deploy/install.sh`);
3. проверяет порты 80/443:
   - **свободны** → поднимает Caddy с автоматическим сертификатом Let's Encrypt;
   - **заняты nginx** → показывает план, после подтверждения добавляет отдельный `server`-блок и выпускает сертификат через certbot (существующие сайты не трогает);
   - **заняты чем-то другим** → ничего не меняет и объясняет, как проксировать вручную;
4. генерирует `.env` с ключами шифрования `DB_KEY` и `FILES_KEY`;
5. запускает контейнеры;
6. создаёт первого пользователя и показывает его временный пароль.

> **Сохраните копию `/opt/zhukonet/.env` отдельно**, например в сейфе или личном менеджере паролей. Без этих ключей база и бэкапы не расшифруются.

> Если сертификат для `sslip.io` не выпускается из-за лимитов Let's Encrypt, используйте бесплатный поддомен [DuckDNS](https://www.duckdns.org) или свой домен: `DOMAIN=...`.

### Первый вход
1. Откройте адрес портала и войдите с временным паролем, затем задайте свой.
2. **Пароли** → создайте хранилище: придумайте мастер-ключ компании и **распечатайте код восстановления**.
3. **Настройки** → вставьте API-токен ZeroTier (my.zerotier.com → Account → API Access Tokens), если нужна синхронизация.
4. **Сотрудники** → «Добавить»: каждый получит логин и временный пароль.
5. **Telegram-бот** (по желанию):
   - создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`), вставьте токен в **Настройки → Telegram-бот**;
   - добавьте бота в канал **администратором** с правом публикации, укажите канал (`@имя` или ссылку `https://t.me/имя`), нажмите «Тест в канал»;
   - каждый сотрудник: **Отметки → Мой Telegram → Привязать** и нажимает Start в боте.

   Бот работает через long polling — входящий порт и вебхук не нужны, серверу нужен лишь исходящий доступ к `api.telegram.org` (можно заменить переменной `TG_API_URL`). Сообщения в канал начинаются со дня, следующего за подключением бота. Данные клиентов, которые сотрудник открывает в боте, проходят через серверы Telegram.

### Обслуживание

```bash
cd /opt/zhukonet
sudo ./deploy/update.sh                                     # обновиться до последней версии
sudo docker compose logs -f app                             # логи
sudo docker compose exec app node dist/cli.js create-user ivan "Иван Петров"
sudo docker compose exec app node dist/cli.js reset-password ivan   # если сотрудник забыл пароль
```

**Бэкап.** Настройки → «Скачать бэкап» выдаёт ZIP с зашифрованной базой и файлами. Восстановление описано в `RESTORE.txt` внутри архива: остановить `app`, распаковать в `data/`, проверить, что в `.env` те же ключи, запустить.

## Разработка

```bash
npm run install:all && npm ci
export DB_KEY=$(openssl rand -hex 32) FILES_KEY=$(openssl rand -hex 32) COOKIE_SECURE=0   # запомните ключи: с другими база не откроется
cd server && npm run cli -- create-user admin "Админ"   # первый пользователь (данные в server/data)
npm run dev                                              # API на :8080
# в другом терминале:
cd web && npm run dev                                    # фронтенд на :5173, /api проксируется на :8080
```

Проверки: `npm run typecheck`, `npm test` (unit + API), `npm run e2e` (Playwright по запущенному порталу, нужны переменные `ADMIN_PASSWORD` и `BASE_URL`).
